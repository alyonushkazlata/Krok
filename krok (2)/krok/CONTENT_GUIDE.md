# Як писати теми для платформи «Крок»

Цей документ — єдине джерело правди для авторів матеріалів. Читай його повністю перед роботою.

## Для кого це

Учень (14–16 років), який хоче **зрозуміти**, а не завчити. Він може відкрити тему після канікул і не пам’ятати нічого. Тому кожна тема має:

1. пояснити **простими словами, навіщо** це потрібно і **звідки береться** правило («розжувати»);
2. дати точне означення/правило;
3. показати **алгоритм** («як це робити»);
4. розібрати **приклади з ходом думок**, не лише викладками;
5. попередити про **типові помилки**;
6. дати **багато різноманітних задач** із підказками, які ведуть до відповіді, і розбиттям на кроки.

Мова — українська, звертання на «ти». Короткі речення. Без поблажливого тону, без канцеляриту. Терміни — за шкільною програмою України (НУШ; 10 клас — профільний рівень). Матеріали пишемо **самі**, оригінальними словами: не копіюємо підручники.

## Файли

Одна тема = один файл `packages/content/src/<предмет>/g<клас>/<id>.topic.ts`, наприклад
`packages/content/src/algebra/g8/a8-vieta.topic.ts`. Ім’я файлу = `id` теми (`<id>.topic.ts`).
Для `g6` (5–6 класи) папка `g6`, для 10 класу `g10`.

Карта програми (id, назви, розділи, передумови) **уже задана** у `packages/content/src/<предмет>/curriculum.ts` — id і `chapter` бери звідти (не змінюй їх; передумови з карти застосовуються автоматично). Тема, якої немає в карті, не підключиться.

**Зразки (обов’язково прочитай обидва, вони задають планку якості):**
- `packages/content/src/algebra/g8/a8-quad-formula.topic.ts` — алгебра: інтуїція, означення, графіки, алгоритм, 3 приклади, 12 шаблонів задач, кроки, підказки.
- `packages/content/src/geometry/g7/g7-angles.topic.ts` — геометрія: малюнки (`figure`, `crossing`), задачі з малюнком.

Допоміжні функції — `packages/content/src/lib/` (`tex.ts`, `build.ts`, `figures.ts`). Типи — `packages/core/src/types.ts`. **Не змінюй** нічого поза власними файлами тем. Якщо потрібна допоміжна функція — напиши її локально у своєму файлі теми.

Каркас файлу:

```ts
import { choiceAnswer, exercise, frac, poly, topicFactory /* ... */ } from '../../lib'
const topic = topicFactory('algebra', 8)           // предмет і клас
export default topic('a8-3', {                      // id розділу з curriculum.ts
  id: 'a8-vieta', title: '…', summary: '…', prereqs: [], estMinutes: 30,
  lesson: [ { title: '…', blocks: [ … ] } ],
  examples: [ … ], formulas: [ … ], mistakes: [ … ],
  exercises: [ exercise('id', 1, 'коротко: який навик', (rng) => ({ prompt, answer, hints, solution, steps })) ],
})
```

(`prereqs: []` у файлі ігнорується — береться з curriculum.ts, але поле обов’язкове за типом.)

## Планка якості для кожної теми

**Теорія (`lesson`)** — 3–5 розділів (`title`), у кожному кілька блоків:
- `intuition` («Простими словами») — образ, аналогія, навіщо; кожна тема має принаймні один.
- `definition`, `rule` — точні формулювання (формули в `$…$` / `$$…$$`).
- `algorithm` — «Як це робити» для типових задач (4–7 кроків).
- `figure` — малюнки для геометрії; **графіки** для функцій/нерівностей (див. нижче).
- `check` («Перевір себе») — 1–3 міні-питання з відповіддю та поясненням.
- `warning` — найтиповіша пастка. `tip` — корисний лайфхак/зв’язок з іншими темами.
- Якщо правило не очевидне — додай «чому так» (коротке обґрунтування/виведення) блоком `text`.

**Приклади (`examples`)** — 3–4 розібраних: від простого до складнішого; у кожному кроці `think` (що думаємо і чому) + `do` (запис). Останній приклад — «підступний» (пастка, особливий випадок).

**Задачі (`exercises`)** — **8–12 шаблонів**, складності 1/2/3 (приблизно 3/5/3), різні **типи** задач (обчислити, спростити, розв’язати, знайти помилку, вибрати правильну відповідь, текстова задача, задача з параметром/НМТ-стилю для складності 3). Кожен шаблон:
- генерує **різні числа** (не менше ~20 різних умов); при будь-якому seed не кидає помилок;
- має `hints` — **2–3 підказки від м’якої до майже готової** (перша — «з чого почати/що згадати», остання — майже крок розв’язання, але не відповідь);
- має `solution` — масив повних пояснених рядків розв’язання (цифри обчислюй кодом, не вписуй руками);
- для складності 2–3 (і для багатокрокових задач) — `steps`: 2–4 підпитання, що ведуть до розв’язання («Розбити на кроки»); у кожного кроку `prompt`, `answer`, `hint`, `explanation`. Мінімум 3 шаблони теми мають `steps`;
- `skill` — короткий опис навику («Скоротити дріб розкладанням»), він показується учню у «Слабких місцях».

**Довідка**: `formulas` (3–8 штук, `tex` без `$`), `mistakes` (3–5: `wrong` / `why` / `right`).

**НМТ**: для 10 класу та де доречно додавай завдання складності 3 у стилі НМТ/ЗНО (коротка відповідь числом, вибір із 4–5 варіантів, відповідність).

## Типи відповідей (`AnswerSpec`)

| Коли | Як | Що вводить учень |
|---|---|---|
| число, дріб, корінь | `{ kind: 'number', value, tolerance? }` | `0,75`, `3/4`, `2√3`, `π/6` |
| вираз зі змінними | `{ kind: 'expression', value: 'x^2-4x+4', rejectLiteral?, rejectMessage? }` | будь-який еквівалентний запис |
| рівняння прямої тощо | `{ kind: 'equation', value: 'y = 2x + 3' }` | `y=2x+3`, `2x-y+3=0` |
| корені | `{ kind: 'numberSet', values: [2, -3] }` (порожній масив = «немає коренів») | `2; -3` |
| пара/трійка | `{ kind: 'tuple', values: [1, -2] }` | `(1; -2)` |
| проміжок | `{ kind: 'interval', value: '(-inf; 2] U [5; +inf)' }` | `(-∞;2]∪[5;+∞)`, `x≤2 або x≥5` |
| вибір | `choiceAnswer(rng, правильний, [помилкові…])` (варіанти перемішуються) | клік |
| слово | `{ kind: 'text', accept: ['бісектриса'] }` | текст |

Правила:
- Відповідь має бути **однозначною**: умова не повинна допускати двох правильних, але різних відповідей. Для ірраціональних значень у `number` використовуй точне значення (`Math.sqrt(2)*3`), допуск за замовчуванням 1e-6.
- Якщо просиш «спростити/розкласти/звести до вигляду» — додай `rejectLiteral: [початковий вираз]` (інакше учень просто перепише умову і отримає «правильно»).
- Для кутів/відстаней: у `prompt` пиши «(у градусах)» / «(у см)» і приймай число.
- Для відповідей-виразів із кількома коренями, π тощо — `inputHint` підкаже формат (`Приклад запису: -1+√3; -1-√3`).
- `answerTex` (LaTeX без `$`) — гарний запис відповіді для показу.
- Коли відповідь «немає розв’язків», використовуй `numberSet` з `values: []` або для проміжків `interval` зі значенням `∅`.

## Малюнки (`Figure`) — геометрія та графіки

```ts
import { figure, polar, triangleFromSides, fitView, rotate, mid, dist } from '../../lib'
const f = figure({ A: [0,0], B: [4,0], C: [1,3] }, [
  { t: 'poly', pts: ['A','B','C'], fill: 'ink' },                 // трикутник із заливкою
  { t: 'seg', a: 'A', b: 'B', ticks: 1, label: 'c' },             // відрізок з позначкою рівності
  { t: 'angle', at: 'A', from: 'B', to: 'C', label: 'α', right: false }, // дуга ПРОТИ годинникової від променя at→from до at→to
  { t: 'angle', at: 'B', from: 'C', to: 'A', right: true },       // прямий кут (квадратик)
  { t: 'circle', c: 'O', r: 2 }, { t: 'line', a: 'A', b: 'B', style: 'dashed' },
  { t: 'arrow', a: 'A', b: 'B', label: 'a⃗' }, { t: 'dot', at: [1,1] }, { t: 'text', at: [1,1], text: '5 см' },
], { width: 320, labelOffsets: { O: [10, -12] }, caption: 'Підпис з $LaTeX$' })
```

- Точки (`points`) автоматично підписуються (літерами) з відступом від центру фігури; тонке налаштування: `labelOffsets` (піксельний зсув: `dx` вправо, `dy` вниз) або `hideLabels`.
- Дуга кута малюється **від променя `from` до променя `to` проти годинникової стрілки** — вибери порядок так, щоб дуга охоплювала потрібний кут (< 180° для внутрішніх кутів). Підписи кутів (`label`) — простий текст (грецькі літери, `°` ок), не LaTeX.
- Усередині `Figure` усі підписи — простий текст; LaTeX працює лише у `caption`.
- Графіки: `axes: true` + `{ t: 'plot', expr: 'x^2-4x+3', color: 'ink', holes?: [x…] }`, `view: [xmin, ymin, xmax, ymax]`. Вираз — синтаксис math.js (`sqrt(x)`, `abs(x)`, `sin(x)`, `x^2`, `1/x`). Графік обривається на розривах автоматично.
- Малюнок у задачі (`figure` у `Problem`) обов’язковий там, де без нього умова незрозуміла. Геометричні фігури будуй за **справжніми координатами** (щоб пропорції були правдоподібні: прямий кут справді прямий, рівні відрізки справді рівні). Для генерованих задач підбирай координати з параметрів (див. `crossing` у зразку).
- Не вказуй на малюнку відповіді.

## LaTeX і текст

- Формули — `$…$` та `$$…$$`. У TypeScript рядках **подвоюй зворотний слеш**: `'$\\frac{a}{b}$'`. (Одинарний `\frac` у рядку ламається — `npm run validate` це знайде.)
- Десяткова кома: використовуй `num()`, `dec()` з lib (`1{,}5`). Дроби — `frac(n, d)` або `\\dfrac`.
- Тригонометрія: `\\operatorname{tg}`, `\\operatorname{ctg}`, `\\arcsin`, `\\operatorname{arctg}`; проміжки через крапку з комою: `(-\\infty;\\, 2]`; множини `\\{2;\\,-3\\}`.
- Градуси: `30^\\circ`. Кут: `\\angle ABC`. Трикутник: `\\triangle ABC`. Паралельність: `\\parallel`. Перпендикулярність: `\\perp`. Вектор: `\\vec{a}`. Подібність: `\\sim`.
- Допустимі markdown-прикраси: `**жирний**`, `*курсив*`, списки `- пункт` і `1. пункт`. Таблиць та заголовків у markdown немає.
- Усі тексти будуть показані також у Telegram-боті простим текстом, тому не покладайся лише на малюнок і не використовуй рідкісні LaTeX-команди (`\\begin{array}`, `\\xrightarrow`, кольори `\\color`).
- Підказки (`hints`) і кроки розв’язання показуються **inline** — не пиши в них блокові `$$…$$`.

## Правильність — головне

Помилка в математиці гірша за відсутність матеріалу.
- Усі числа в `solution`/`explanation`/відповіді **обчислюй кодом** із тих самих змінних, що й умову. Не пиши цифри руками.
- Будуй задачу «від відповіді» (спершу корені/сторони/кути, потім умова), щоб числа виходили гарні й розв’язок існував. Генератор не повинен кидати помилку (не роби «retry через throw»: підбирай параметри у циклі або конструктивно).
- Перевір, що **для всіх** згенерованих варіантів: відповідь існує, однозначна, не вироджена (знаменник ≠ 0, трикутник існує, корінь під радикалом ≥ 0, ОДЗ дотримано).
- Теорія — лише те, що точно знаєш. Означення, теореми, формули, умови застосовності — перевір двічі. Не вигадуй «правил» і не переказуй сумнівне. Для 10 класу використовуй позначення профільної програми.
- Не посилайся на номери підручників.

## Перевірка

З кореня репозиторію:

```
npm run validate -- <id1> <id2> ...        # перевірка вибраних тем
SEEDS=80 npm run validate -- <id>          # більше варіантів
```

Скрипт перевіряє: усі генератори на десятках seed (не кидають помилок; власна правильна відповідь зараховується; є підказки та розв’язання; різноманітність умов), структуру теми, LaTeX через KaTeX, одинарні `\` у рядках, відсутність NaN/undefined. **Тема не здана, поки `validate` не проходить без помилок.**
Додатково: `npm run typecheck` (TypeScript має проходити).

Не запускай `npm install`, не змінюй `package.json`, `curriculum.ts`, `lib/`, `core/`, `apps/`. Не торкайся чужих файлів тем.

## Що повернути
